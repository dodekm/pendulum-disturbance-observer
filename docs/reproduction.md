# Reproduction notes

The recorded-data workflow uses MATLAB R2025b Update 2 with Optimization Toolbox. The toolbox is used when fitting the nuisance initial velocity for the frozen validation predictions. The repository layout is part of the workflow. Start MATLAB at the repository root and run [reproduce_pendulum_revision.m](../reproduce_pendulum_revision.m).

The main entry point checks the files listed in [supplement_manifest.json](../supplement_manifest.json) before running. It replays 68 completed control runs and one timing-interlock record, compares the three control cohorts against their archived run-level CSVs, checks the excitation coverage, and computes the reported diagnostics on the frozen models. It writes a reproduction report and separate results for each cohort. Set the optional OutputDirectory argument to a new writable path if you want to keep regenerated files outside the repository.

The model registry is in [experiment_framework/model_registry](../experiment_framework/model_registry/). The [identification results](../experiment_data/campaign_v2/identification_results/) retain the selected fit and the preceding result used for seeding. The 13 inspected development recordings, the nine-record numerical fit mask, and the three fresh holdouts serve different roles. The archived model-use decision preserves the failed peak-error targets. The fitted actuator lag was used for prediction while the controller and disturbance observer used the nominal second-order dynamics.

The [Arduino sketch and actuator interface](../Arduino/pendulum_BLDC_bidir/) and acquisition MATLAB functions are provided for provenance. The sketch depends on Rob Tillaart’s [AS5600 library](https://github.com/RobTillaart/AS5600), version 0.6.6 as recorded in the original source. The historical build placed its source under src/AS5600 within the sketch folder. The offline analysis runs without the Arduino toolchain, a UART device, or the platform-specific acquisition binary. Original machine paths in the archived run metadata are kept as provenance. The entry point resolves its inputs within the local repository.
